# 21 周学习计划 · 2026.09.20 → 2027.02

> 起点：会 Python 基础语法
> 目标：成都/重庆 AI 应用开发岗，7-12K 档
> 投入：全职，每天 6-8 小时，每周 6 天
> 节奏：第 12 周开始投递练手，第 20 周正式下场

---

## 一、每天怎么过（固定模板）

| 时段 | 时长 | 做什么 |
|---|---|---|
| 上午 | 1 小时 | 看新知识（文档/视频） |
| 上午 | 2 小时 | **动手写代码** |
| 下午 | 3 小时 | **动手写代码** |
| 晚上 | 1 小时 | 复盘 + 写笔记 + 提交 GitHub |

**写代码 : 看视频 ≥ 7 : 3。** 这是整份计划里最重要的一条。一天 6 小时里看 4 小时视频，等于没学。

**每天必须有一次 GitHub 提交。** 哪怕只是改了一行。你的提交记录本身就是简历的一部分。

---

## 二、第 0 周（9/20-9/26）：环境 + GitHub 起步

这一周不学新知识，只做一件事：**把工具链搭起来，让代码能跑、能传。**

| 天 | 任务 |
|---|---|
| 第 1 天 | 装 Python 3.11+ 和 VS Code。写一个 `hello.py` 并运行成功 |
| 第 2 天 | 注册 GitHub 账号。建第一个仓库 `python-practice` |
| 第 3 天 | 装 Git。学 `git add` / `commit` / `push` 三条命令，把 hello.py 传上去 |
| 第 4 天 | 学命令行：`cd` / `ls` / `mkdir` / `python xxx.py` |
| 第 5 天 | 写 3 个小脚本（打印九九乘法表、猜数字游戏、计算器）并提交 |
| 第 6 天 | 给仓库写一个 README，说明这个仓库是干什么的 |

**验收**：GitHub 上能看到你的仓库和 4 个以上的文件，而且是你自己传上去的。

---

## 三、阶段一（第 1-4 周）：Python 打牢

**这是整份计划的地基。跳过它，后面全塌。**

### 第 1 周：数据结构
列表、字典、集合、元组的常用操作（增删改查、切片、推导式）
**产出**：写一个通讯录小程序，用字典存人名和电话，支持增删查

### 第 2 周：函数与文件
函数（参数、返回值、默认值）、文件读写、异常处理 try/except
**产出**：写一个程序，读取一个 txt 文件，统计每个词出现的次数，输出到新文件

### 第 3 周：模块与外部库
import、pip、虚拟环境、requests 库、JSON 和 CSV 处理
**产出**：调用一个公开 API（天气/汇率/笑话都行），把返回的 JSON 存成 CSV

### 第 4 周：面向对象 + 综合练习
类、属性、方法（够用就行，别死磕）
**产出**：把前三周的小程序用类重构一遍；再写一个「批量重命名文件」工具

**验收标准**：给你一个没做过的需求（比如「把这个文件夹里所有 txt 合并成一个，按日期排序」），你能**不看教程独立写出来**。

达不到就重复第 1-4 周，不要往下走。

---

## 四、阶段二（第 5-7 周）：工程基础

### 第 5 周：Git 进阶 + Linux
分支、合并、解决冲突；Linux 常用命令（ls/cd/cat/grep/chmod/ps）
**注意**：Linux 命令是 20 份 JD 里的高频要求，别跳过

### 第 6 周：HTTP 与 API
HTTP 方法、状态码、请求头响应体；用 Postman 或 curl 调接口；理解 RESTful
**产出**：用 requests 调 3 个不同的公开 API，写清楚每个接口的参数和返回

### 第 7 周：数据库
SQLite 起步；SQL 基础（增删改查、where、order by、join）
**产出**：写一个记账程序，数据存进 SQLite，重启不丢

**验收**：能说清楚「一个 HTTP 请求从发出到拿到返回，中间发生了什么」。

---

## 五、阶段三（第 8-10 周）：后端开发

### 第 8 周：FastAPI 入门
路由、路径参数、Pydantic 请求体校验
### 第 9 周：FastAPI 进阶
依赖注入、异步 async/await、错误处理
### 第 10 周：完整项目

**产出（重点）**：一个待办事项 API
- 增删改查四个接口 + 数据库持久化
- 代码传 GitHub，README 写清楚怎么跑
- 能用 Postman 测通每个接口

**验收**：能画出请求处理的流程图，讲清楚每一步。

> **第 12 周开始投递练手**——那时候你大概在这个阶段，项目还没成型，但可以去投几家感受一下市场。被拒是正常的，当信息看。

---

## 六、阶段四（第 11-13 周）：大模型应用基础

**从这周开始碰 AI。前面没打牢的话，这里会变成抄教程。**

### 第 11 周：LLM 概念 + 调用 API
token、上下文窗口、temperature、幻觉怎么来的、成本怎么算
选一家 API（通义/DeepSeek/智谱），学会基本调用
### 第 12 周：Prompt 工程
结构化提示词、few-shot、思维链（CoT）
**产出**：做一个命令行问答机器人，能连续对话
### 第 13 周：流式输出 + 多轮对话
实现打字机效果；管理对话历史

**产出**：一个能连续对话、有流式输出的命令行 AI 助手，传 GitHub。

---

## 七、阶段五（第 14-16 周）：RAG

**这是成都 AI 岗出现频率最高的关键词，认真做。**

### 第 14 周：切分 + Embedding
文本怎么切（按段/按字数/按语义）、Embedding 是什么、向量是什么
### 第 15 周：向量数据库
Chroma 上手：存、查、相似度检索
### 第 16 周：完整链路 + 调优
文档导入 → 切分 → 向量化 → 检索 → 拼上下文 → 生成

**产出（重点）**：一个 RAG 问答应用。
**建议就用你桌面上那套《深度学习入门》资料当知识库**——用自己的材料做，你会更有动力，也更容易发现真实问题。

**验收**：不看资料能讲清楚 RAG 每一步在干什么、为什么这么做、效果不好时可能是什么原因。

---

## 八、阶段六（第 17-18 周）：Agent + Docker

### 第 17 周：Docker
写 Dockerfile、docker run、docker-compose
**为什么必须学**：20 份 JD 里几乎每个 AI 岗都提 Docker，而且一两周就能上手，投入产出比极高
**产出**：把上周的 RAG 应用用 Docker 打包跑起来

### 第 18 周：工具调用与 Agent
Function Calling 原理；模型决定调工具 → 执行 → 结果喂回 → 再决策
**产出**：给 RAG 应用加上工具调用（查天气、算数、查数据库）

---

## 九、阶段七（第 19-20 周）：项目打磨 + 求职

### 第 19 周：整合与包装
把 RAG + Agent + Docker 整合成一个完整项目
- README：做什么、架构图、怎么跑、截图
- 补上索引说明、错误处理
### 第 20 周：简历 + 正式投递
- 一页简历，项目放最上面
- 整理常见问题（RAG 全流程、Prompt 技巧、Agent 设计）
- 开始批量投递

---

## 十、三条铁律

**一、每天必须写代码。** 没写代码的那一天，等于没学习。

**二、每个阶段必须有产出物。** 没有产出物的学习是假的。验收标准达不到，就重复，不要往下堆。

**三、GitHub 从第一天开始传。** 不要等项目做完才传。这 20 份 JD 里反复出现「提供 GitHub 链接」——**在成都市场，一个能打开看的项目比任何证书都有说服力**。
