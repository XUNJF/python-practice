# 第 14 天学习笔记 · 网页界面

> 前端负责「显示和交互」，后端负责「干活」。两者靠 HTTP 连接。

## 一、网页三件套

| | 管什么 | 类比 |
|---|---|---|
| **HTML** | **内容**——页面上有什么 | 骨架 |
| **CSS** | **外观**——长什么样 | 皮肤 |
| **JavaScript** | **行为**——点了按钮干什么 | 肌肉 |

**今天只写 HTML 和一点 JavaScript，不碰 CSS。**

---

## 二、HTML 的结构

```html
<!DOCTYPE html>              ← 声明这是 HTML5
<html lang="zh">             ← 根元素，zh 表示中文
<head>                       ← 给浏览器看的（不显示）
    <meta charset="UTF-8">   ← 编码声明，不写中文可能乱码
    <title>页面标题</title>   ← 浏览器标签页上的名字
</head>
<body>                       ← 给人看的（显示在页面上）
    ...
</body>
</html>
```

### ⚠️ `<head>` 和 `<body>` 的区别

| | 给谁看 | 显示吗 |
|---|---|---|
| `<head>` | 浏览器 | ❌ |
| `<body>` | 人 | ✅ |

### ⚠️ 标签要成对

```html
<h1>标题</h1>        ← 开始标签 + 结束标签（结束的带斜杠）
```

**但浏览器很宽容**——拼错或漏了闭合标签，它一般不会报错，只是渲染结果不对。

**好处**：新手不容易卡死。
**坏处**：写错了没人提醒你，得自己盯。

## 三、常用标签

| 标签 | 作用 | 例子 |
|---|---|---|
| `<h1>` ~ `<h6>` | 标题，数字越小字越大 | `<h1>大标题</h1>` |

| `<button>` | 按钮 | `<button>点我</button>` |
| `<div>` | 容器（用来分组、布局） | `<div>...</div>` |
| `<br>` | 换行（**不用闭合**） | `第一行<br>第二行` |

## 四、两个重要的属性

### `id` —— 给元素起名字

```html
<input id="question">
```

**作用**：让 JavaScript 能按名字找到它。

```javascript
document.getElementById("question")    // 按 id 找
```

**`id` 在一个页面里必须唯一**——不能有两个元素叫同一个名字。

### `placeholder` —— 输入框里的灰色提示

```html
<input placeholder="输入你的问题">
```

**用户一开始打字，它就消失。** 它**不是**输入框的值。

## 五、事件：`onclick`

```html
<button onclick="send()">发送</button>
```

**意思：点一下，就执行叫 `send` 的函数。**

**这是「事件驱动」的概念**——某件事发生（点击），就做某件事（调用函数）。

## 六、⭐ JavaScript 部分逐行讲

```javascript
async function send(){
    const q = document.getElementById("question").value;
    const r = await fetch("/chat?question=" + encodeURIComponent(q), {method:"POST"});
    const data = await r.json();
    document.getElementById("answer").textContent = data.answer;
}
```

### ① `async function send(){ ... }`

定义一个函数。**`async` 表示「里面有需要等待的操作」**——不加的话，里面的 `await` 会报错。

### ② 拿到用户输入

```javascript
const q = document.getElementById("question").value;
```

| 部分 | 意思 |
|---|---|
| `document` | 整个页面 |
| `getElementById("question")` | 按 id 找到那个元素 |
| `.value` | 取它的值（用户打的字） |
| `const q = ...` | 存进变量 `q` |

### ③ 发请求（最关键的一行）

```javascript
const r = await fetch("/chat?question=" + encodeURIComponent(q), {method:"POST"});
```

**`fetch` 就是 JavaScript 版的 `requests`：**

| Python | JavaScript |
|---|---|
| `requests.post(网址)` | `fetch(网址, {method:"POST"})` |
| `response` | `await fetch(...)` |

**`await` = 「等这个做完再往下走」。** 不写的话，请求还没回来代码就往下跑了。

**`encodeURIComponent(q)`** = URL 编码。**中文不能直接放进网址，必须先转码。** 忘了这步，中文问题会出错。

**`{method:"POST"}`** = 指定用 POST（不写默认 GET）。

### ④ 解析返回的 JSON

```javascript
const data = await r.json();
```

**跟 Python 的 `response.json()` 完全一样。**

### ⑤ 把答案显示出来

```javascript
document.getElementById("answer").textContent = data.answer;
```

| 部分 | 意思 |
|---|---|
| `getElementById("answer")` | 找到那个空段落 |
| `.textContent = ...` | 把它的文字设成…… |
| `data.answer` | 后端返回的答案 |

**`data.answer` 里那个 `answer`** —— 就是 Python 里 `return {"answer": answer}` 的那个键名。**两边靠这个名字对上。**

## 七、完整数据流

```
用户打字 → 点「发送」
            ↓
        send() 执行
            ↓
        拿到输入框的字            ②
            ↓
        fetch 发到 /chat          ③
            ↓
  ★ 后端（Python）★
        FastAPI 收到 → bot.chat() → DeepSeek → 返回 {"answer": "..."}
            ↓
        JavaScript 拿到 JSON      ④
            ↓
        填进页面                  ⑤
            ↓
        用户看到回答
```

## 八、`fetch("/chat?...")` 为什么用相对路径

**斜杠开头 = 「跟当前页面同一个地址」：**

```
当前页面  http://127.0.0.1:8000
发到      http://127.0.0.1:8000/chat
```

**好处**：以后部署到别的网址，这段代码不用改。

## 九、CORS（以后一定会遇到的坑）

**如果页面不是由 FastAPI 发出去的**（比如双击文件打开，地址是 `file:///...`），浏览器会拦住请求：

```
Access to fetch at 'http://127.0.0.1:8000/chat' from origin 'null'
has been blocked by CORS policy
```

### 原因：同源策略

**浏览器规定：一个页面只能请求「跟它同源」的地址。**

**「同源」= 协议 + 域名 + 端口 全都一样。**

```
http://127.0.0.1:8000   ← 页面
http://127.0.0.1:8000   ← 请求的地址    ✅ 同源
http://127.0.0.1:3000   ← 换了个端口    ❌ 不同源
```

**为什么这么设计**：防止恶意网站偷偷用你的身份去请求银行网站。

### 你现在不会遇到

因为页面是 FastAPI 自己发出去的，**同源**。

### 以后做前后端分离时会遇到

前端跑在 3000 端口、后端在 8000，就不同源了。解法是在 FastAPI 加几行：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],        # 允许所有来源（生产环境要写具体域名）
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**现在不用加，先知道有这回事。**

## 十、怎么让 FastAPI 发网页

```python
from fastapi.responses import FileResponse

@app.get("/")
def index():
    return FileResponse("index.html")
```

**原来 `/` 返回 JSON，现在返回一个 HTML 文件。**

**一个服务可以同时：**

```python
@app.get("/")            →  返回网页（给人看）
@app.post("/chat")       →  返回 JSON（给程序用）
@app.get("/add")         →  返回 JSON
```

**「返回什么」由你决定**——这是「接口」的本质。

## 练习 3（可选）：加一个「清空」按钮

在页面上加一个按钮，点了能清空输入框和答案：

```html
<button onclick="clearAll()">清空</button>
```

然后在 `<script>` 里加一个函数：

```javascript
function clearAll(){
    document.getElementById("question").value = "";
    document.getElementById("answer").textContent = "";
}
```

**注意对比**：

- 输入框用 `.value = ""`
- 段落用 `.textContent = ""`

**为什么不一样**：「输入框的值」和「段落的文字」是两种不同的东西。
