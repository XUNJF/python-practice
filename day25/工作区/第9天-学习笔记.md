## 一、POST 不是 GET

| | GET | POST |
|---|---|---|
| 意思 | 「把数据给我」 | 「这些内容你处理一下」 |
| 参数放哪 | 网址里（`?t=123`） | **请求体**里 |
| 代码 | `requests.get(url)` | `requests.post(url, json=...)` |
| 典型场景 | 查天气、看列表 | 提交表单、跟 AI 对话 |

**为什么用 POST**：你跟 AI 说的话可能很长，塞网址里不现实。POST 把数据放在请求体里，想放多少放多少。

---

## 二、⚠️ API Key —— 今天最重要的一节

### Key 是什么

一串像 `sk-xxxxxxxx` 的字符，**相当于你的身份证 + 钱包**：

- 服务商靠它认人
- 服务商靠它**从你账户扣钱**

### 放在哪

请求头里：

```python
headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json",
}
```

`Bearer` 是固定写法，后面跟一个空格，再跟你的 Key。

### ⚠️⚠️ 绝对不要把 Key 写进代码

**你的 GitHub 仓库是公开的，一旦推上去，全世界都能看到。**

后果很实际：

1. 别人拿你的 Key 调接口，**账单算你头上**
2. GitHub 上有**专门的爬虫扫公开仓库里的 Key**，几分钟内就能抓走
3. 换 Key 也麻烦——得去后台重置，还得改代码

**每年都有人因为这件事被扣几千上万。**

### 正确做法：Key 单独放文件，让 git 忽略

**`key.txt`**（只放 Key，什么都不加）：
```
sk-xxxxxxxxxxxxxxxxxxxx
```

**`.gitignore`** 里加一行：
```
key.txt
```

**代码里读它**：
```python
with open("key.txt", encoding="utf-8") as f:
    api_key = f.read().strip()
```

**`.strip()` 不能省**——从文件读出来的字符串末尾常带换行符 `\n`，会让 Key 验证失败。**这个坑几乎人人都会踩一次。**

## 三、请求体长什么样

```python
{
    "model": "deepseek-chat",
    "messages": [
        {"role": "user", "content": "你好"}
    ]
}
```

### `messages` 是列表，元素是字典

**你前几天学的列表和字典，在这里碰上了。**

```python
"messages": [                              # ← 列表
    {"role": "user", "content": "你好"},    # ← 字典
    {"role": "assistant", "content": "..."},
    {"role": "user", "content": "再问一句"},
]
```

### `role` 是「谁在说话」

| role | 意思 |
|---|---|
| `"user"` | 用户说的 |
| `"assistant"` | AI 回复的 |
| `"system"` | 给 AI 的设定 |

**多轮对话就是把历史都放进去**——每问一次，就把之前的对话加上新的问题一起发过去。**AI 本身不记得任何东西**，它「记得」是因为你每次都把历史重新发了一遍。

（这一点很重要，后面做多轮对话全靠它。）

---

## 四、响应长什么样

```python
{
    "choices": [
        {
            "message": {
                "role": "assistant",
                "content": "你好！有什么可以帮你的？"
            }
        }
    ]
}
```

### 取内容要一层层剥

```python
answer = data["choices"][0]["message"]["content"]
```

| 步骤 | 得到什么 | 类型 |
|---|---|---|
| `data["choices"]` | 所有备选回答 | 列表 |
| `[0]` | 第一个 | 字典 |
| `["message"]` | 那条消息 | 字典 |
| `["content"]` | AI 说的话 | 字符串 |

**为什么是列表**：有些接口可以一次生成多个备选回答，所以用列表装着。**大多数时候只有 `[0]` 那一个。**

**嵌套结构就是这样一层层取的**——跟读 JSON 文件一模一样。

## 五、完整代码骨架

```python
import requests

# 1. 读 Key（不要写死在代码里！）
with open("key.txt", encoding="utf-8") as f:
    api_key = f.read().strip()

# 2. 准备请求头
headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json",
}

# 3. 准备请求体
payload = {
    "model": "deepseek-chat",
    "messages": [
        {"role": "user", "content": "你好，请用一句话介绍你自己"}
    ],
}

# 4. 发请求（注意是 post）
response = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers=headers,
    json=payload,
    timeout=30,
)

# 5. 检查状态码
if response.status_code == 200:
    data = response.json()
    answer = data["choices"][0]["message"]["content"]
    print(answer)
else:
    print(f"请求失败：{response.status_code}")
    print(response.text)      # 把错误详情打出来，方便排查
```

**`json=payload` 这个参数**：requests 会自动把字典转成 JSON，并自动设置好 `Content-Type` 头。**不用你手动 `json.dumps()`。**

---

## 六、状态码对照（大模型接口）

| 状态码 | 意思 | 怎么办 |
|---|---|---|
| `200` | 成功 | — |
| `401` | Key 不对 / 没带 Key | 检查 `key.txt` 内容、有没有多余空格换行 |
| `402` | 余额不足 | 去充值 |
| `429` | 请求太频繁 | 慢一点，加 `time.sleep` |
| `500` | 对方服务器问题 | 等一会儿重试 |

---

## 七、`response.text` 是你的救星

**调接口出错时，第一件事是 `print(response.text)`。**

它会把服务器返回的原始内容打出来——通常包含**具体的错误原因**。

```python
else:
    print(f"状态码：{response.status_code}")
    print(f"错误详情：{response.text}")
```

**光看状态码只知道「失败了」，看 text 才知道「为什么失败」。**

# 常见报错

| 报错 | 原因 | 怎么修 |
|---|---|---|
| `401 Authentication Fails` | Key 错 / 有空格换行 | 检查 `key.txt`，加 `.strip()` |
| `KeyError: 'choices'` | 返回结构不对（通常是报错了） | `print(response.text)` 看真实内容 |
| `ModuleNotFoundError: requests` | 不在虚拟环境里 | 激活 venv |
| `SSLError` | 网络/代理问题 | 检查梯子状态 |
