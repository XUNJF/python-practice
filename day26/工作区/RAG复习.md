## 0. 一分钟速览

```
问题 → 检索（Retrieval）→ 找到最相关的几段 → 拼进 prompt（Augmented）→ 发给 AI → 基于资料回答（Generation）
```

**RAG 全名 Retrieval-Augmented Generation：**

| 词 | 意思 | 对应动作 |
|---|---|---|
| **Retrieval** | 检索 | 找出最相关的几段（第 17 天） |
| **Augmented** | 增强 | 把资料拼进 prompt（第 18 天） |
| **Generation** | 生成 | 让 AI 基于资料回答（第 18 天） |

**一句话记住 RAG 的价值：把模型从「凭记忆回答」变成「开卷考试」。**

## 1. 为什么要 RAG

### 要解决的问题：幻觉

大模型的训练数据是公开数据，**它不知道你的私人资料**。
你问它「我那份产品手册里写了什么」，它要么说不知道，要么**编一个听起来很像的答案**。
这就是「幻觉」的主要来源之一：**模型不知道自己在瞎编。**

### 笨办法为什么不行：把资料全塞进 prompt

```
200 页产品手册 + 用户的问题 → 一起发给 AI
```

| 问题 | 说明 |
|---|---|
| **太长** | 超出上下文限制，模型一次能看的字数是有限的 |
| **太贵** | 每次提问都要把整本手册重发一遍 |
| **效果反而差** | 无关信息太多，模型抓不住重点 |

⚠️ 第三条最反直觉：**给的信息多，不等于答得好。关键信息被淹没在噪音里，模型反而更容易答偏。**

### RAG 的解法

只给 AI「跟这个问题相关的那几段」，而不是「所有资料」：

- 不超长度限制（只发几段）
- 不贵（每次都很少）
- 效果好（全是相关内容）

## 2. 第一步：检索（Retrieval）

### 2.1 传统搜索 vs 语义搜索

| | 传统搜索 | RAG 用的语义搜索 |
|---|---|---|
| 依据 | 关键词匹配 | 意思相近 |
| 例子 | 搜「退款」只找到含「退款」二字的段落 | 「我买错了想退钱怎么办」也能找到退款政策 |
| 缺点 | 用户换个说法、一个字都不重合就找不到 | —— |

### 2.2 语义搜索怎么做到：把文字变成数字

```
"退款"    →  [0.12, -0.83, 0.45, ...]      1024 个数字
"退货"    →  [0.11, -0.79, 0.48, ...]      ← 跟上面很接近
"服务器"  →  [-0.67, 0.22, -0.31, ...]     ← 差很远
```

**含义相近的文字 → 数字串也相近。**

### 2.3 Embedding（嵌入）关键概念

**把一段文字变成一串数字的过程，叫 embedding；那串数字叫「向量」（vector）。**

| 概念 | 意思 |
|---|---|
| **Embedding** | 动作：文字 → 向量 |
| **向量** | 结果：那串数字 |
| **维度** | 数字的个数（bge-m3 是 1024 维） |

**三个必须知道的点：**

1. **同一段文字，每次 embedding 出来结果一样。** 不像大模型有随机性——同样的输入，永远同样的输出。
2. **向量本身没有意义。** `[0.12, -0.83, ...]` 里每个数字代表什么没人能解释，它是 1024 维空间里的坐标，无法可视化。你只需关心一件事：**两段文字的向量离得近不近。**
3. **不同模型的向量不能混用。** 两个模型各自的空间坐标放在一起比较毫无意义。**换模型 = 所有数据必须重新向量化。**

### 2.4 怎么算「接近」：余弦相似度

算两个向量的夹角：

| 结果 | 意思 |
|---|---|
| 接近 **1.0** | 意思几乎一样 |
| **0.5 ~ 0.9** | 相关 |
| 接近 **0** | 基本无关 |
| **负数** | 意思相反（少见） |

> 不用管公式，记住「越大越像」就行。

**参考数值（bge-m3 实测）：**

| 对比 | 相似度 |
|---|---|
| "想退货怎么办" vs "退款政策：30天内可全额退款" | **0.70** |
| "想退货怎么办" vs "服务器日志保留七天" | **0.50** |

差 0.2，不算夸张，**但排序是对的——RAG 靠的就是这个排序。**

**余弦相似度实现（只用基础语法）：**

```python
import math

def cosine(a, b):
    dot = 0                      # 分子：对应位置相乘再相加（有多同向）
    for i in range(len(a)):
        dot += a[i] * b[i]

    len_a = 0                    # 分母：两个向量各自的长度
    for x in a:
        len_a += x * x
    len_b = 0
    for x in b:
        len_b += x * x

    # 相除 = 消掉长度影响，只看方向
    return dot / (math.sqrt(len_a) * math.sqrt(len_b))
```

### 2.5 调用 embedding 服务（实操要点）

**DeepSeek 没有 embedding 接口，需要另注册一家。** 选**硅基流动（SiliconFlow）**：

- `siliconflow.cn`，国内服务，**不用梯子**
- `BAAI/bge-m3` 模型**标着免费**
- 接口格式跟 DeepSeek 一样（OpenAI 兼容）

**步骤**：手机号注册 → 实名认证 → 新建 API 密钥 → key 存进 `key_sf.txt` → **`.gitignore` 里加一行 `key_sf.txt`**，用 `git status` 确认被挡住。

⚠️ **坑：接口地址是 `.cn` 不是 `.com`**
```
https://api.siliconflow.cn/v1/embeddings
                   ↑↑ 必须 .cn，写错成 .com 会连不上
```

**调用的样子（跟调 DeepSeek 几乎一样，只是换了网址和字段）：**

```python
import requests

with open("key_sf.txt", encoding="utf-8") as f:
    sf_key = f.read().strip()

response = requests.post(
    "https://api.siliconflow.cn/v1/embeddings",
    headers={
        "Authorization": f"Bearer {sf_key}",
        "Content-Type": "application/json",
    },
    json={"model": "BAAI/bge-m3", "input": "退款政策：购买后30天内可申请全额退款。"},
    timeout=30,
)

vector = response.json()["data"][0]["embedding"]
print(len(vector))     # 1024
```

**跟 chat 接口的三个区别：**

| | chat 接口 | embedding 接口 |
|---|---|---|
| 网址 | `/chat/completions` | **`/embeddings`** |
| 请求体 | `"messages": [...]` | **`"input": "一段文字"`** |
| 返回值 | `choices[0].message.content` | **`data[0].embedding`** |

## 3. 第二步：增强 + 生成（Augmented + Generation）

### 3.1 缺的那一环

第 17 天只做到：`问题 → 检索 → 找到最相关的几段 → 【停】`
**找到的资料 AI 根本不知道**，它们只是被排了个序、打印在终端上。

补上后半截：
```
问题 → 检索 → 找到几段 → 拼进 prompt → 发给 AI → 基于资料回答
                              ↑ 这一步叫「生成」Generation
```

### 3.2 怎么把资料「塞」进 prompt

就是把它们**拼成一段文字**，作为 `user` 消息发给大模型：

```
请根据下面的资料回答问题。

【资料】
1. 退款政策：购买后30天内可申请全额退款。
2. 配送说明：全国包邮，偏远地区需加收运费。

【问题】
我想退货怎么办？
```

**两个要点：**

1. **「资料」和「问题」必须分开标** —— 用 `【】`、`====`、`---` 都行，关键视觉上分得开，否则模型分不清哪句是资料、哪句是问话。
2. **资料要带编号** —— 让模型能说「根据资料 1……」，**这就是出处（引用）。带出处的回答，是 RAG 相对普通聊天最大的优势。**

### 3.3 ⭐ 最关键的一句 system（整个 RAG 里最重要，没有之一）

```
你是一个客服助手。

只根据下面提供的【资料】回答用户的问题。
如果资料里没有相关信息，就直说「资料里没有提到这个问题」，
不要凭自己的知识回答。
```

**没有这句，RAG 就是白做的。**
原因：模型训练数据里有一堆通用知识，**你给了资料它也不一定老实照办**——会把自己的知识掺进来，甚至无视资料自己编。**结果比不做 RAG 更糟**，因为你以为它有依据，实际它在瞎说。

**为什么非要限制它「不许用自己的知识」：**

```
你给的资料：  本店退款政策：购买后 30 天内可全额退款。
它训练时学的：一般电商是 7 天无理由退货。
不加限制可能答：本店支持 7 天无理由退货。  ← 编的，而且很自信
```

**RAG 的目的不是让模型更聪明，是让模型「只看你给的材料」。**
类比：**开卷考试——学生如果非要凭记忆答题，那还不如不给他书。**

### 3.4 资料放在哪：两种拼接方式

**方式 A：放在 user 消息里（简单，推荐）**
```python
system = "你是一个客服助手。只根据【资料】回答，资料里没有就说不知道。"
user = f"""【资料】
{context}

【问题】
{question}"""
messages = [
    {"role": "system", "content": system},
    {"role": "user", "content": user},
]
```

**方式 B：把资料放进 system**
```python
system = f"""你是一个客服助手。只根据下面【资料】回答。

【资料】
{context}
"""
```

两种都能用，差别在于资料算「长期设定」还是「这一次的输入」。
**推荐 A** —— 每次提问的资料都不一样，它属于「这一次的输入」，不该放进 system。

### 3.5 `context` 怎么拼

```python
hits = search(question, top_k=3)      # 检索结果：[(分数, 文档), ...]

context = ""
for i, (score, doc) in enumerate(hits):
    context += f"{i+1}. {doc}\n"
```

`enumerate` 就是「边遍历边给出序号」，结果：

```
1. 退款政策：购买后30天内可申请全额退款。
2. 配送说明：全国包邮，偏远地区需加收运费。
3. 会员权益：会员可享受9折优惠和优先客服。
```

### 3.6 完整流程：`ask(question)`

```python
def ask(question):
    # ① 检索
    hits = search(question, top_k=3)

    # ② 拼资料
    context = ""
    for i, (score, doc) in enumerate(hits):
        context += f"{i+1}. {doc}\n"

    # ③ 拼 prompt
    messages = [
        {"role": "system", "content": "只根据【资料】回答，资料里没有就说不知道。"},
        {"role": "user", "content": f"【资料】\n{context}\n【问题】\n{question}"},
    ]

    # ④ 发给大模型
    response = requests.post(
        "https://api.deepseek.com/chat/completions",
        headers={"Authorization": f"Bearer {ds_key}", "Content-Type": "application/json"},
        json={"model": "deepseek-chat", "messages": messages},
        timeout=30,
    )

    return response.json()["choices"][0]["message"]["content"]
```

⭐ **注意第 ④ 步——跟第 9 天写的完全一样。**
**RAG 没有新的 API，没有新库。就是「先检索，把结果拼进 prompt，再走一遍你早就会的流程」。**

## 4. 怎么验证 RAG 有没有用

**对比着跑，最能说明问题：**

| 问题 | 不加 RAG | 加了 RAG |
|---|---|---|
| 「你们退款几天内可以」 | 可能答「7天」（编的） | 答「30天」（根据资料） |
| 「你们支持货到付款吗」 | 编一个 | **说「资料里没有提到」** |

**第二种情况最关键——它承认自己不知道。**
**这才是 RAG 的价值：不是答得更好，是「不知道就说不知道」。**

**验证练习：**

```python
print(ask("我想退货怎么办"))
print(ask("你们支持货到付款吗"))     # ← 资料里没有，看它怎么答

# 对照：同一问题跑两次，一次带资料，一次不带
messages = [{"role": "user", "content": "你们退款几天内可以"}]
messages = [{"role": "user", "content": f"【资料】\n{context}\n【问题】\n你们退款几天内可以"}]
```

**如果它说「资料里没有提到」，说明 RAG 做对了。**
**如果两个答案不一样、不带资料的那个在编——你就亲眼看到了 RAG 的意义。**

## 5. 常见报错 / 问题排查

### embedding 接口报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `401` | key 不对 | 检查 `key_sf.txt`，别忘了 `.strip()` |
| 连不上 | 域名写成 `.com` 了 | 改成 `.siliconflow.cn` |
| `404 model not found` | 模型名写错 | 确认是 `BAAI/bge-m3` |
| `402` | 余额不足 | 确认用的是免费模型 |
| `KeyError: 'data'` | 返回结构不对（通常已报错） | `print(response.text)` 看真实内容 |

### RAG 效果问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 模型无视资料，自己编 | system 里没写「只根据资料」 | 加那句限制 |
| 模型把资料和问题搞混 | 没分开标记 | 用【】分隔清楚 |
| 资料明明有，它说没有 | 检索没检索到（召回问题） | 调大 `top_k`，或改检索方式 |
| 答对了但不给出处 | system 里没要求 | 加「回答时注明根据哪条资料」 |
