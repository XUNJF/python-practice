## 一、为什么要做网络服务

你现在那个 `ChatBot` 类：

```python
bot = ChatBot("...")
print(bot.chat("什么是变量？"))
```

**只能你自己在终端里跑。** 别人想用，得：

1. 装 Python
2. 装 requests
3. 拿到你的代码
4. 在终端里跑

**这不可能给用户用。**

**做成网络服务之后**：任何能发 HTTP 请求的东西都能用它——网页、手机 App、微信小程序。

```
现在：  你 → 终端 → ChatBot
明天：  任何程序 → HTTP 请求 → 你的服务 → ChatBot
```

**这就是「接口」的意义**：把能力暴露出去，让任何程序都能调用。

（你之前一直在**调用别人**的接口——DeepSeek 的。明天你**自己造一个**。）

---

## 二、装 FastAPI

```bash
pip install fastapi uvicorn
```

**两个包：**

| 包 | 干什么 |
|---|---|
| `fastapi` | 框架本体，定义接口用 |
| `uvicorn` | **服务器**，负责把服务跑起来 |

**为什么要两个**：FastAPI 负责「定义规则」，uvicorn 负责「实际运行」。就像写剧本（FastAPI）和演戏（uvicorn）是两件事。

---

## 三、最小的服务

新建 `main.py`：

```python
from fastapi import FastAPI

app = FastAPI()                 # 创建应用


@app.get("/")                   # ← 装饰器：这个函数管「根路径」
def read_root():
    return {"message": "你好，这是我的第一个接口"}
```

**跑起来：**

```bash
uvicorn main:app --reload
```

**`main:app` 是什么意思**：

```
main  :  app
 ↑        ↑
文件名    里面的 FastAPI 实例名
（main.py）  （app = FastAPI()）
```

**`--reload`**：改了代码自动重启（开发时很爽，不用手动重启）

**然后浏览器打开：**

```
http://127.0.0.1:8000
```

**你会看到：**

```json
{"message": "你好，这是我的第一个接口"}
```

**看到这个，你就成功造出了人生第一个接口。**

## 四、⭐ 装饰器是什么

```python
@app.get("/")
def read_root():
    ...
```

**`@app.get("/")` 就是装饰器。** 它做的事很简单：

> **给下面这个函数贴个标签，告诉 FastAPI：「这个函数负责处理 `/` 这个网址」**

**没有这个装饰器，FastAPI 根本不知道有这个函数。**

### 换个角度看

```python
@app.get("/")          →  访问 http://127.0.0.1:8000/
@app.get("/hello")     →  访问 http://127.0.0.1:8000/hello
@app.post("/chat")     →  用 POST 访问 http://127.0.0.1:8000/chat
```

**装饰器里的字符串，就是网址路径。**

**`@app.get` vs `@app.post`**：

| 装饰器 | 对应 | 什么时候用 |
|---|---|---|
| `@app.get("/x")` | GET 请求 | 「给我数据」 |
| `@app.post("/x")` | POST 请求 | 「我要发数据给你」 |

**跟你第 9 天学的 `requests.get` / `requests.post` 是同一个概念**——只不过那天你是**发**请求的人，现在你是**接**请求的人。

## 五、完整例子（两个接口）

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "服务正常运行"}


@app.get("/hello")
def say_hello():
    return {"message": "你好呀"}


@app.get("/add")
def add(a: int, b: int):
    return {"result": a + b}
```

**第三个接口很有意思**——它接收参数：

```
http://127.0.0.1:8000/add?a=3&b=5
```

**返回：**

```json
{"result": 8}
```

**注意函数签名 `def add(a: int, b: int)`**：

- **参数名 `a`、`b`** → 对应网址里 `?a=3&b=5`
- **`: int`** → **类型标注**，告诉 FastAPI「这个参数必须是整数」

**FastAPI 会自动帮你检查类型**——如果你传 `?a=abc`，它会自动报错，说「a 必须是整数」。

**这个 `: 类型` 的写法你以后会天天见**，它是 FastAPI 的核心特性之一。

## 六、⭐ 自动生成的文档

**服务跑起来之后，浏览器打开：**

```
http://127.0.0.1:8000/docs
```

**你会看到一个自动生成的、能直接点击测试的 API 文档页面。**

每个接口、要传什么参数、返回什么，**全自动列出来了**，还能直接在页面上点「Try it out」测试。

**这是 FastAPI 最出名的特性**，也是它在国内火起来的原因之一。**别的框架要额外写文档，它不用。**

（还有个备用版本：`/redoc`，长得不一样，功能类似。）

## 七、把 ChatBot 接进去（今天的重点）

**你之前写的东西，直接能用。**

假设 `chat_bot.py` 里有个 `ChatBot` 类，`main.py` 里这样写：

```python
from fastapi import FastAPI
from chat_bot import ChatBot

app = FastAPI()
bot = ChatBot("你是一个Python助教")


@app.get("/")
def read_root():
    return {"message": "ChatBot 服务运行中"}


@app.post("/chat")
def chat(question: str):
    answer = bot.chat(question)
    return {"answer": answer}
```

**注意 `from chat_bot import ChatBot`**——**这就是你第 8 天学的「模块」**：

```
chat_bot.py     →  一个模块
ChatBot         →  模块里的类
from ... import →  从模块里导入类
```

**看，第 8 天学的东西现在用上了。**

### 用起来

**浏览器打开 `/docs`，找到 `/chat`，点「Try it out」，输入问题，点「Execute」。**

**你会看到 AI 的回答出现在页面上。**

**到这一步，你的助手就不是「一个脚本」了，是「一个服务」。**

## 八、`--reload` 和端口

### `--reload`

```bash
uvicorn main:app --reload
```

改了代码，服务自动重启。**开发时一定加。**

**不加的话**，你改了代码但没生效，会以为是 bug，其实是服务还跑着旧代码。**这个坑很浪费生命。**

### 端口

默认 8000。想换：

```bash
uvicorn main:app --reload --port 9000
```

**端口被占用**（8001 报 `Address already in use`）就换一个。

### 怎么停掉服务

在终端里按 **`Ctrl + C`**。

## 九、常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: fastapi` | 没装，或不在 venv 里 | 激活 venv 再装 |
| `Address already in use` | 端口被占用 | 换端口，或关掉旧的服务 |
| 浏览器打不开 | 服务没跑起来 | 看终端有没有报错 |
| 改了代码没生效 | 没加 `--reload` | 加上，或手动重启 |
| `Error loading ASGI app` | `main:app` 写错 | 确认文件名是 `main.py`、变量名是 `app` |
