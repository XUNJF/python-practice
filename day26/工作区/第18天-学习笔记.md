# 第 18 天学习笔记 · RAG 闭环

> 检索完之后，把资料喂给大模型，让它基于资料回答。
> **这一步做完，才是完整的 RAG。**

---

## 一、现在缺哪一环

**第 17 天做的：**

```
问题 → 检索 → 找到最相关的几段 → 【停】
```

**找到的资料，AI 根本不知道。** 它们只是被排了个序、打印在终端上。

**今天补上后半截：**

```
问题 → 检索 → 找到几段 → 拼进 prompt → 发给 AI → 基于资料回答
                              ↑ 今天做这一步
                              （这一步叫「生成」Generation）
```

**所以 RAG 的全名是 Retrieval-Augmented Generation：**

| 词 | 意思 | 你哪天做的 |
|---|---|---|
| **Retrieval** | 检索 | 第 17 天 |
| **Augmented** | 增强（把资料塞进 prompt） | **今天** |
| **Generation** | 生成（让 AI 基于资料回答） | **今天** |

---

## 二、怎么把资料「塞」进 prompt

**就是把它们拼成一段文字。**

**结构：**

```
请根据下面的资料回答问题。

【资料】
1. 退款政策：购买后30天内可申请全额退款。
2. 配送说明：全国包邮，偏远地区需加收运费。

【问题】
我想退货怎么办？
```

**这段文字作为 `user` 消息发给大模型。**

### 两个要点

**① 「资料」和「问题」必须分开标**

**不标清楚的话，模型分不清哪句是你给的资料、哪句是用户的问话。**

**用 `【】`、`====`、`---` 这类标记隔开都行**，关键是**视觉上要分得开**。

**② 资料要带编号**

**编号是为了让模型能说出「根据资料 1……」—— 这就是出处（引用）。**

**带出处的回答，是 RAG 相对普通聊天最大的优势。**

---

## 三、⭐ 最关键的一句 system

**这是整个 RAG 里最重要的一段话，没有之一：**

```
你是一个客服助手。

只根据下面提供的【资料】回答用户的问题。
如果资料里没有相关信息，就直说「资料里没有提到这个问题」，
不要凭自己的知识回答。
```

**没有这句，RAG 就是白做的。**

**为什么**：模型的训练数据里有一堆「通用知识」，**你给了资料它也不一定老实照办**——它会把自己的知识掺进来，甚至完全无视你给的资料，自己编一个。

**结果比不做 RAG 更糟**——因为你以为它有依据，实际上它在瞎说。

---

## 四、为什么非要限制它「不许用自己的知识」

**听起来很反直觉**：我们花钱用大模型，为什么要限制它？

**因为它的大部分训练知识，对具体业务来说是错的。**

**举个例子：**

```
你给它的资料：  本店退款政策：购买后 30 天内可全额退款。

它训练时学到的：一般电商是 7 天无理由退货。

不加限制，它可能答：本店支持 7 天无理由退货。
                   ↑ 编的，而且很自信
```

**RAG 的目的不是让模型更聪明，是让模型「只看你给的材料」。**

**记住这句话**：**RAG 把模型从「凭记忆回答」变成「开卷考试」。** 开卷考试的学生如果非要凭记忆答题，那还不如不给他书。

## 五、常见的拼接方式

### 方式 A：放在 user 消息里（简单，推荐先用）

```python
system = "你是一个客服助手。只根据【资料】回答，资料里没有就说不知道。"

user = f"""【资料】
{context}

【问题】
{question}"""

messages = [
    {"role": "system", "content": system},
    {"role": "user", "content": user},
]
```

### 方式 B：把资料放进 system（有些做法这么做）

```python
system = f"""你是一个客服助手。只根据下面【资料】回答。

【资料】
{context}
"""
```

**两种都能用。** 差别在于**资料算「长期设定」还是「这一次的输入」**。

**推荐 A** —— 因为**每次提问的资料是不一样的**，它属于「这一次的输入」，不该放进 system。

## 六、`context` 怎么拼

**把检索出来的几段文档拼成一个字符串。**

```python
hits = search(question, top_k=3)      # 检索结果：[(分数, 文档), ...]

context = ""
for i, (score, doc) in enumerate(hits):
    context += f"{i+1}. {doc}\n"
```

**结果：**

```
1. 退款政策：购买后30天内可申请全额退款。
2. 配送说明：全国包邮，偏远地区需加收运费。
3. 会员权益：会员可享受9折优惠和优先客服。
```

**（`enumerate` 是「边遍历边给出序号」——你之前见过，`for i, fruit in enumerate(fruits)`。）**

## 七、完整流程

```python
def ask(question):
    # ① 检索
    hits = search(question, top_k=3)

    # ② 拼资料
    context = ""
    for i, (score, doc) in enumerate(hits):
        context += f"{i+1}. {doc}\n"

    # ③ 拼 prompt
    messages = [
        {"role": "system", "content": "只根据【资料】回答，资料里没有就说不知道。"},
        {"role": "user", "content": f"【资料】\n{context}\n【问题】\n{question}"},
    ]

    # ④ 发给大模型
    response = requests.post(
        "https://api.deepseek.com/chat/completions",
        headers={"Authorization": f"Bearer {ds_key}", "Content-Type": "application/json"},
        json={"model": "deepseek-chat", "messages": messages},
        timeout=30,
    )

    return response.json()["choices"][0]["message"]["content"]
```

**看出来了吗——④ 跟第 9 天写的完全一样。**

**RAG 没有新的 API，没有新库。** 就是「先检索，把结果拼进 prompt，再走一遍你早就会的流程」。

## 八、验证 RAG 有没有用的方法

**对比着跑，最能说明问题。**

| 问题 | 不加 RAG | 加了 RAG |
|---|---|---|
| 「你们退款几天内可以」 | 可能答「7天」（编的） | 答「30天」（根据资料） |
| 「你们支持货到付款吗」 | 编一个 | **说「资料里没有提到」** |

**第二种情况最关键** —— **它承认自己不知道。**

**这才是 RAG 的价值：不是答得更好，是「不知道就说不知道」。**

---

## 九、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 模型无视资料，自己编 | system 里没写「只根据资料」 | 加那句限制 |
| 模型把资料和问题搞混 | 没分开标记 | 用【】分隔清楚 |
| 资料明明有，它说没有 | 检索没检索到（召回问题） | 调大 `top_k`，或改检索方式 |
| 答对了但不给出处 | system 里没要求 | 加「回答时注明根据哪条资料」 |
