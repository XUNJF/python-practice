## 二、市场要什么（成都 + 杭州两批 JD 合并结论）

两批 JD 方向一致，都是 **Python + RAG + Agent**，差别只在深浅：

| 关键词 | 成都（20 份） | 杭州（22 份） | 对你意味着 |
|---|---|---|---|
| RAG | 最高频 | 16+ | **必须扎实，你在做** |
| **Agent / 工具调用** | 高 | **18+ / 9+** | **下一个主攻方向** |
| LangChain / LangGraph | 中 | 14+ | 原理通了之后再上 |
| 向量数据库 | 中高 | 10+ | **要会用一种（Chroma）** |
| Docker / Linux | 很高 | 10+ | 必备，门槛低，性价比高 |
| FastAPI | 中（AI 岗几乎都写） | 10+ | 方向对 |
| MCP | — | 6+ | 知道有这回事 |
| AI Coding 工具 | 出现（JD 16） | 5+ | **你已经在积累，是优势** |

**两条战略结论（原 JD 分析里的，重申）：**

1. **靶心是 7–12K**（成都档），别被 15–30K 焦虑到。第一份工作进门，第二份再跳。
2. **突破口是「AI 工具驱动开发」类岗位**（JD 16 那类）：不要经验、不要多语言，只要「能做出东西 + 讲清楚怎么做的」。**你已经在用 Claude 学、改代码、调 bug——这本身就是被明码标价的技能，只是一直没意识到该写出来。**

**成都 vs 杭州的差别一句话：**
> 成都要求你「会用」，杭州要求你「能讲清楚为什么」。
> 而这个差别，只能靠「自己动手做过一遍」补上，背概念没用。

## 三、接下来两周：具体做什么

**原则：不要横向铺开。现在手上最值钱的是「RAG 已经手动跑通」这件事，把它变成「可展示的项目」，比再去学十个新概念都强。**

### 第 1 步：把 RAG 从「几条硬编码短句」升级成「真实文档」

这是当前最大的缺口，也是**面试最可能问的地方**。

- [ ] **补「切分」这一课**：拿《深度学习入门》里一章，试着切成段落。
      - 先按「空行 / 段落」切（最简单）
      - 再试「按固定字数切」（比如每 300 字一段，段间留重叠）
      - 观察：切太大 / 切太小，检索结果有什么变化
- [ ] **补第 16 天的 Chroma**：把切好的段落存进 Chroma，用它的检索替代你手写的 `cosine`。
      - 对比：手写的 `search()` 结果 vs Chroma 的结果，差别在哪
      - 这一步做完，「向量数据库」这个 JD 关键词就落地了

### 第 2 步：把 RAG 变成一个「能打开看的东西」

现在的 `ask()` 只在命令行里跑。**GitHub 上一个能打开看的项目 > 任何证书**（两批 JD 反复提）。

- [ ] 给 RAG 套一个简单的网页界面（你第 13–15 天已经写过 HTML 前端 + `/chat` 接口，直接复用）
