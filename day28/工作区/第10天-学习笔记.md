# 第 10 天学习笔记 · system 角色

> Prompt Engineering 的入口。所有「智能客服」「专属助手」的第一步。

---

## 一、`system` 是什么

**给 AI 的说明书，不是你说的话。**

```python
messages = [
    {"role": "system", "content": "你是一个Python助教"},   # ← 说明书
    {"role": "user",   "content": "什么是变量？"},          # ← 你说的话
]
```

**位置：永远放第一位。**

---

## 二、和 `user` 的区别

| | `system` | `user` |
|---|---|---|
| 谁说的 | **你（开发者）** | **用户** |
| 生效范围 | 整段对话，一直有效 | 就那一次 |
| 作用 | 定规则 | 提要求 |
| 用户看得到吗 | 通常看不到 | 看得到 |

**比喻：**

- `system` = **入职培训**：「你是客服，说话要客气，不知道的别瞎编」
- `user` = **今天的工作**：「帮我查一下订单」

**培训一次，管一整天。** 用户提一百个问题，`system` 都在生效。

---

## 三、它能控制什么

| 维度 | 例子 |
|---|---|
| **身份** | 「你是一个资深Python工程师」 |
| **语气** | 「用轻松口语化的方式回答」 |
| **长度** | 「每次回答不超过三句话」 |
| **格式** | 「用 Markdown 表格对比」 |
| **面向谁** | 「对方是零基础新手」 |
| **边界** | 「不确定的就说不知道，不要编」 |
| **禁止** | 「不要输出代码，只讲思路」 |

---

## 四、写 system 的几个原则

### ① 越具体越好

**模糊**：
```
你是一个好助手
```

**具体**：
```
你是一个Python助教。对方会基础语法但不熟练。
回答格式：先给结论，再解释原因，最后给一个例子。
不要用太专业的术语，非用不可时要解释。
```

**「好助手」等于什么都没说**——AI 本来就是个助手。「好」这个字它不知道指什么。

### ② 说清楚「要什么」，比说「不要什么」有效

**差**：
```
不要回答得太长
```

**好**：
```
回答控制在三句话以内
```

**告诉它「往哪走」，比告诉它「别往哪走」更有效。**

### ③ 复杂任务分条列

```
你的任务：
1. 判断用户的问题属于哪个类别
2. 用一句话概括问题
3. 给出解决步骤

输出格式：
类别：
概括：
步骤：
```

**分条写，AI 更容易照着执行。** 一大段话它抓不住重点。

### ④ 给例子（few-shot）

**这是 Prompt Engineering 里最有效的技巧之一。**

```
把用户的话改写成正式书面语。

例子：
输入：这玩意儿不好使
输出：该功能无法正常使用

输入：你们这咋这么慢
输出：请问处理进度为何较慢

现在处理：这东西太贵了
```

**给两三个例子，AI 就明白你要什么格式了。** 比写一百字描述管用。

（这个技巧叫 **few-shot**，是后面 JD 里会看到的词。）

## 五、完整代码骨架

```python
import requests

with open("key.txt", "r", encoding="utf-8") as f:
    api_key = f.read().strip()

headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json",
}

messages = [
    {"role": "system", "content": "你是一个Python助教，回答要简洁"},
    {"role": "user",   "content": "什么是变量？"},
]

payload = {
    "model": "deepseek-chat",
    "messages": messages,
}

response = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers=headers,
    json=payload,
    timeout=30,
)

if response.status_code == 200:
    data = response.json()
    print(data["choices"][0]["message"]["content"])
else:
    print(f"状态码：{response.status_code}")
    print(response.text)
```

**注意：`system` 那一条也放在 `messages` 列表里**，只是它的 `role` 是 `"system"`。

## 六、多轮对话里怎么用

```python
messages = [
    {"role": "system", "content": "你的说明书"}      # ← 只加一次
]

while True:
    question = input("你：")
    if question == "退出":
        break
    messages.append({"role": "user", "content": question})
    # ...发请求...
    messages.append({"role": "assistant", "content": answer})
```

**`system` 写在循环外面**——因为它不需要重发，它一直在列表第一位。**循环里只 append 用户和 AI 的话，不要去动第一条。**

---

## 七、真实产品里怎么用

**所有你见过的「AI 客服」「AI 老师」「AI 写作助手」，第一步都是写一个 system。**

比如你以后要做「Python 学习助手」：

```python
SYSTEM_PROMPT = """
你是一个Python学习助手，帮助一个正在从零学Python的人。

背景：
- 对方会基础语法（变量、循环、函数、列表、字典），但不熟练
- 目标是找AI应用开发的工作

回答要求：
1. 先给结论，再解释为什么
2. 能用生活例子就用
3. 给代码时加注释
4. 对方写错了直接指出，不要客气
5. 如果问题超出Python基础范围，提醒对方这不是当前该学的
"""
```

**写一次，以后每次对话都带着它。** 这就是「产品化」的开始。

---

## 八、常见坑

| 坑 | 说明 |
|---|---|
| `system` 放在 `user` 后面 | 通常无效，必须放第一位 |
| 说明书太长太杂 | 重点被稀释，AI 抓不住。**宁短勿杂** |
| 只在第一轮放，后面忘了 | 每轮请求都要带上（所以放在 `messages` 列表里） |
| 期望它 100% 遵守 | **AI 不是程序，`system` 是「引导」不是「强制」**。写得再好也可能偶尔不听话 |

**最后这条最重要**：`system` 是**强烈建议**，不是**硬性规则**。**它大部分时候会听，但不是 100%。** 真正要「强制」的约束，得在代码层面处理（比如检查输出格式，不对就重试）。

## 练习 1：对比实验 ⭐

**同一个问题，三种 `system`，看回答差多少。**

不加循环，`system` 写死，跑三次（每次改一下 system 内容）：

```python
# 第一轮
{"role": "system", "content": "你是一个专业的Python助教"}

# 第二轮
{"role": "system", "content": "你是一个面向小学生的老师，用最通俗的话解释"}

# 第三轮
{"role": "system", "content": "回答必须控制在20个字以内"}
```

**问题都是**：`什么是变量？`

**把三次回答记下来对比。** 你会直观感受到 system 的影响。
