# 第 12 天学习笔记 · 异常处理（try/except）

> 让程序「出错了也不会死」。真实产品必备。

---

## 一、为什么需要

你现在的代码：

```python
response = requests.post(...)      # 网络一抖 → 程序整个崩掉
```

**报错长这样：**

```
Traceback (most recent call last):
  ...
requests.exceptions.ConnectionError: HTTPSConnection...
```

**整个程序死掉**，之前聊的对话也没了。

**这在真实产品里是不可接受的**——用户网络断一下，应用就崩？没人会用。

---

## 二、基本语法

```python
try:
    # 可能出错的代码
    response = requests.post(...)
except requests.RequestException as e:
    # 出错时怎么办
    print(f"网络出问题了：{e}")
```

**读作**：「试着执行 try 里的代码；如果抛出了 `RequestException` 这类错误，就执行 except 里的。」

**`as e`** —— 把错误对象装进变量 `e`，可以打印、记录、做判断。

---

## 三、三个部分

```python
try:
    # 可能出错的
except 某类错误 as e:
    # 出错时的处理
else:
    # 没出错时执行（可选，很少用）
finally:
    # 不管出不出错都执行（可选）
```

**最常用的是 `try` + `except`。** `else` 和 `finally` 你现在基本用不到。

### `finally` 什么时候有用

**「不管成功失败，都必须做的事」**。比如：

```python
f = open("data.txt")
try:
    content = f.read()
finally:
    f.close()          # 不管读成功没，都要关文件
```

**但用 `with` 就不需要 `finally` 了**（`with` 自动帮你关）——**所以你更用不上了。**

---

## 四、⭐ 捕获哪类错误

**错误是分种类的。** 你得指定捕获哪一种：

```python
try:
    ...
except requests.Timeout:
    print("请求超时了，稍后再试")
except requests.ConnectionError:
    print("连不上服务器，检查网络")
```

### 常见错误类型

| 错误 | 什么意思 | 常见场景 |
|---|---|---|
| `requests.Timeout` | 超时 | 对方太慢，或网络慢 |
| `requests.ConnectionError` | 连不上 | 断网、域名错、被墙 |
| `requests.HTTPError` | HTTP 状态码是错误 | 4xx / 5xx |
| `requests.RequestException` | **上面全部的父类** | 兜底 |

**注意**：`requests.RequestException` 是**所有网络错误的父类**——`Timeout` 和 `ConnectionError` 都归它管。

```python
except requests.RequestException as e:      # 能捕获所有网络错误
```

**新手建议：先用这一个兜住所有网络问题。**

等你发现「超时要重试、连不上要提示检查网络」这种**需要区别对待**的场景，再细分成多个 `except`。

### ⚠️ 千万别写裸的 except

```python
except:                    # ✗✗ 不要这样
    pass
```

**这会捕获「所有」错误**——包括你自己代码里的 bug（比如变量名打错）。

**后果**：真正的 bug 被吞掉了，程序「看起来正常」，但结果是错的。**这是最难查的一类问题。**

**至少写成：**

```python
except Exception as e:
    print(f"出错了：{e}")
```

**最好写明具体类型：**

```python
except requests.RequestException as e:
    ...
```

## 五、出错时要有返回值

```python
def chat(self, question):
    self.messages.append({"role": "user", "content": question})

    try:
        response = requests.post(..., timeout=30)
    except requests.RequestException as e:
        print(f"网络出问题了：{e}")
        return None                    # ← 关键
    ...
```

**为什么必须 `return None`**：

**不写的话，Python 默认返回 `None`**，但调用的人**分不清**：

- 「返回 None」= 失败了？
- 「返回 None」= 回答内容正好是空的？

**显式写出来，语义就明确了。**

调用的人就可以这样处理：

```python
answer = bot.chat("你好")
if answer is None:
    print("刚才出问题了，再试一次？")
else:
    print(answer)
```

## 六、完整示例

```python
def chat(self, question):
    self.messages.append({"role": "user", "content": question})

    payload = {
        "model": "deepseek-chat",
        "messages": self.messages,
    }

    try:
        response = requests.post(
            "https://api.deepseek.com/chat/completions",
            headers=self.headers,
            json=payload,
            timeout=30,
        )
    except requests.RequestException as e:
        print(f"网络出问题了：{e}")
        return None

    if response.status_code == 200:
        data = response.json()
        answer = data["choices"][0]["message"]["content"]
        self.messages.append({"role": "assistant", "content": answer})
        return answer
    else:
        print(f"状态码：{response.status_code}")
        print(response.text)
        return None
```

## 七、几个真实场景

### 读文件时

```python
try:
    with open("history.json", encoding="utf-8") as f:
        self.messages = json.load(f)
except FileNotFoundError:
    print("没有历史记录，从头开始")
except json.JSONDecodeError:
    print("历史文件损坏了，忽略它")
```

**这就是你第 9 天那个「空文件导致崩溃」问题的正规解法。** 比 `os.path.exists` 更稳——因为 `exists` 只判断「文件在不在」，**判断不了「内容对不对」**。

### 用户输入时

```python
try:
    num = int(input("请输入数字："))
except ValueError:
    print("你输入的不是数字")
```

**这是你第 4 天那个 `ValueError` 的正规解法。**

## 八、什么时候该用 try/except

**不是「到处都包」**——那会让代码难读。

**判断标准**：

> **这个操作有「合理的失败可能」吗？**

| 场景 | 用不用 |
|---|---|
| 网络请求 | ✓ 必须——网络本来就不稳 |
| 读文件 | ✓ 文件可能不存在、可能是空的 |
| 用户输入转数字 | ✓ 用户可能乱输 |
| 自己写的两行加法 | ✗ 不会失败，包了是噪音 |

**没有失败可能的地方包 try，是过度防御。** 反而掩盖了真 bug。

---

## 九、和 `if` 判断的区别

**同一个场景，两种写法：**

```python
# 写法一：if 判断（事前检查）
if os.path.exists("history.json"):
    ...
else:
    ...

# 写法二：try/except（事后处理）
try:
    ...
except FileNotFoundError:
    ...
```

**Python 社区有个说法叫 EAFP**：「先做，出错了再说」——**更推荐 try/except。**

**为什么**：

- `if` 只能检查「你想得到的失败」，`try` 能接住「你想不到的」
- `if` 要检查一次、执行一次（两次操作），`try` 只有一次

**但 `if` 不是不能用**——**可读性优先**。简单场景用 `if` 更清楚。

**你的建议**：两种都用过，以后凭直觉选。

## 练习 1：给 ChatBot 加上异常处理

在 `chat` 方法里包上 `try/except`：

```python
try:
    response = requests.post(...)
except requests.RequestException as e:
    print(f"网络出问题了：{e}")
    return None
```

**然后测试**：把 `timeout=30` 改成 `timeout=0.001`（人为制造超时），跑一下看看——

- **不加 try** → 程序崩，一大片红字
- **加了 try** → 只打印一行「网络出问题了」

**对比一下，你就知道它的价值了。**

## 练习 2：`load` 也加上

现在的 `load` 遇到损坏的文件会崩。加上处理：

```python
def load(self, filename):
    try:
        with open(filename, encoding="utf-8") as f:
            self.messages = json.load(f)
        print(f"读到了 {len(self.messages)} 条历史记录")
    except FileNotFoundError:
        print("还没有历史记录")
    except json.JSONDecodeError:
        print("历史文件损坏了，忽略")
```

**好处**：类外面就不用写 `if os.path.exists(...)` 了——**判断的责任交给了 `load` 自己。**

这是一次**「把判断收进方法里」**的练习——**也让调用变得更简单**：

```python
bot.load("history.json")      # 一行搞定，不用管文件在不在
```
