# 第 19 天学习笔记 · 切分（Chunking）

> 补上 RAG 的第一步：**把一篇长文档，切成一段一段能检索的小块。**
> 这是「学习总览」里标出的第一个空缺——之前你检索的 `docs` 是几条硬编码的短句，
> 换成真实文档后，「怎么切」就是第一道坎。

---

## 一、为什么必须先切分

**Embedding 一次只能吃一小段文字。**

你不可能把《深度学习入门》整本书喂给 embedding 接口：

| 问题 | 说明 |
|---|---|
| **太长** | 接口对单次输入长度有限制（通常几百到几千 token） |
| **太糊** | 一整章压成一个向量，里面几十个主题全糊在一起，检索时「什么都不像」 |
| **没法定位** | 就算检索到了，你也没法把「整章」当成出处贴给用户 |

**所以：切分是检索的前置条件。** 不切分，embedding 和检索都无从谈起。

**一句话记住：**
> **检索的最小单位，就是你切分的最小单位。**
> 你切得不好，检索就不可能好——**后面所有环节的上限，在这里就被定死了。**

---

## 二、⭐ 先想清楚：切分是为了「检索准」

**这是最容易搞反的地方。**

不是「把文章切得整齐」就行，而是**切出来的每一块，要能回答一类问题**。

**例子**：一段文字里同时讲了「退款天数」和「配送范围」。

- 如果整段切成一块 → 用户问「几天内退款」，这块的向量里混了配送信息，**相似度被稀释，排名靠后**。
- 如果拆成两块 → 「退款天数」那块和问题高度匹配，**排名靠前**。

**所以判断切分好坏，只有一个标准：**
> **拿一个真实问题去搜，该块该不该被搜出来。**
> 不是看切得匀不匀、长不长。

---

## 三、三种切法（由简到繁）

### 切法 A：按段落 / 空行切（最简单，先做这个）

**思路**：作者写文章时，一个段落本身就是一个意思单元。**直接按空行 `\n\n` 切开。**

```python
def split_by_paragraph(text):
    # 按空行切，去掉每段首尾的空白
    parts = text.split("\n\n")
    return [p.strip() for p in parts if p.strip()]
```

| 优点 | 缺点 |
|---|---|
| 极简单，符合人的阅读习惯 | **段落长度不可控**——可能一段 20 字，也可能一段 2000 字 |
| 不会把一句话从中间切断 | 遇到超长段落就没辙（超出 embedding 限制） |

**适用**：结构规整的文档（比如 Markdown 笔记、产品手册）。**这是你第一步该用的切法。**

---

### 切法 B：按固定字数切 + 重叠（最常用，必学）

**思路**：不管作者怎么分段，**我按固定长度硬切**（比如每 300 字一块）。

**两个参数：**

| 参数 | 意思 | 典型值 |
|---|---|---|
| `chunk_size` | 每块多长 | 300 字 |
| `chunk_overlap` | **相邻两块重叠多少字** | 50 字 |

```python
def split_by_size(text, chunk_size=300, overlap=50):
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        # 下一次从「当前位置往回退 overlap 字」开始 —— 这就是重叠
        start = end - overlap
    return chunks
```

**⚠️ 为什么必须重叠（这是关键，面试会问）**

一句话如果正好被切在边界上，**两半各在一块的末尾和开头，哪一块都不完整**。

```
原句：本店规定购买后30天内可以申请全额退款

不重叠切在「30天」中间：
  块1：...本店规定购买后30天
  块2：内可以申请全额退款...
       ↑ 「30天内退款」这句意思被劈开了
```

**加了 overlap**，同样这句话会完整地出现在**块1 的后半段**和**块2 的前半段**里——**至少有一块是完整的，检索就能命中。**

| 优点 | 缺点 |
|---|---|
| 长度可控，不会超出限制 | **可能在句子中间切断**（语义不完整） |
| overlap 兜住了边界问题 | 参数要调（300/50 只是起点，不是标准答案） |

---

### 切法 C：按语义切（进阶，先别急）

**思路**：用模型判断「这里是不是话题变了」，在话题切换处切。

- 更贵、更慢、更复杂
- **现阶段不用做**——成都/杭州 JD 都不要求你自己实现语义切分
- 知道有这回事即可

## 四、⭐ `chunk_size` 的取舍（重要的不是数字，是这个权衡）

**这是切分里最该理解的一件事：切大和切小，各错在哪。**

| | 切太小（比如 100 字） | 切太大（比如 1000 字） |
|---|---|---|
| **好处** | 定位准，向量「纯」 | 上下文完整，不会丢信息 |
| **坏处** | 意思不完整，答不出「为什么」 | 主题混杂，向量「糊」，检索排名差 |
| **症状** | 检索到了，但答案缺一句话 | 检索排名靠后，甚至搜不到 |

**经典的两难：**
> 用户问「退款要几天」——这个答案需要「30天」**和**「需要提供订单号」两条信息。
> 切太小，两条分在两块里，模型只看到一条。
> 切太大，这块混了 5 个主题，相似度被拉低，**根本没被搜出来**。

**实践起步值（先跑起来再调）：**

```
chunk_size = 300   # 字
overlap    = 50    # 字
top_k      = 3     # 检索取前 3 块
```

**调优的方向（结合第 18 天「效果不好怎么排查」）：**

| 现象 | 可能是切分问题 | 怎么调 |
|---|---|---|
| 该搜到的没搜到 | 切太大，主题被稀释 | 调小 `chunk_size` |
| 搜到了但答案不完整 | 切太小，上下文断了 | 调大 `chunk_size` 或调大 `overlap` |
| 答案出现在块边界 | 没重叠 | 加 `chunk_overlap` |
| 检索结果总是那几块 | 切太粗，块数太少 | 调小 `chunk_size`，让块变多 |

## 五、真实文档的坑（用《深度学习入门》时会踩到）

**你手上的资料不是干净的纯文本**，直接切会出问题：

| 坑 | 现象 | 怎么办 |
|---|---|---|
| **Markdown 标题** | 标题被切成单独一块，没内容 | 把标题和下面正文绑在一起切 |
| **代码块** | 代码被从中间切断，等于废了 | 先识别 ```` ``` ```` 区块，整体保留 |
| **表格** | 表格被切散，行列对不上 | 整表保留，或转成文字描述 |
| **PDF 提取的换行** | 每行都有 `\n`，按 `\n\n` 切不动 | 先清洗：把单换行合并 |
| **页眉页脚** | 「第 3 章」重复出现在每块里 | 预处理时删掉 |

**⚠️ 记住这条顺序：**
> **原始文件 → 清洗 → 切分 → 向量化**
> **清洗在切分之前。** 脏文本切出来的块，向量也是脏的。

**PDF 提取的「假空行」问题**（最常见的坑）：
PDF 提取出来常常是每行一个 `\n`，根本没有 `\n\n`。这时按空行切 = 切不动。
要先做一步：

```python
# 把「单个换行」合并成空格，只保留「空行」作为段落分隔
import re
text = re.sub(r"(?<!\n)\n(?!\n)", " ", text)   # 单换行 → 空格
text = re.sub(r"\n{2,}", "\n\n", text)          # 多个空行 → 规范成两个
```

## 六、完整可跑的切分脚本

```python
import re

def load_text(path):
    with open(path, encoding="utf-8") as f:
        text = f.read()
    # 清洗：单换行合并成空格（PDF 提取的假换行）
    text = re.sub(r"(?<!\n)\n(?!\n)", " ", text)
    text = re.sub(r"\n{2,}", "\n\n", text)
    return text.strip()


def split_by_paragraph(text):
    """切法 A：按段落"""
    return [p.strip() for p in text.split("\n\n") if p.strip()]


def split_by_size(text, chunk_size=300, overlap=50):
    """切法 B：按固定字数 + 重叠"""
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        if end >= len(text):
            break
        start = end - overlap
    return chunks


def split_doc(path, method="size", **kw):
    """统一入口：先清洗，再选切法"""
    text = load_text(path)
    if method == "para":
        return split_by_paragraph(text)
    return split_by_size(text, **kw)


if __name__ == "__main__":
    chunks = split_doc("深度学习入门.txt", method="size",
                       chunk_size=300, overlap=50)
    print(f"共切出 {len(chunks)} 块")
    for i, c in enumerate(chunks[:3]):
        print(f"\n--- 块 {i+1}（{len(c)} 字）---")
        print(c)
```

## 八、验收标准（自测）

**不看资料，能讲清楚：**

1. **为什么要切分？** —— embedding 输入有长度限制；整篇压成一个向量会「糊」；检索的最小单位 = 切分的最小单位。
2. **`chunk_overlap` 是干什么的？** —— 防止句子被切在边界上，让「跨边界的关键句」至少完整出现在一块里。
3. **切大 / 切小各错在哪？** —— 切小：上下文断，答案不完整；切大：主题混杂，向量被稀释，检索排名差。
4. **真实文档切分前要先做什么？** —— 清洗（PDF 假换行、页眉页脚、代码块保护），再切。
5. **怎么判断切分好不好？** —— 不是看匀不匀，是拿真实问题去搜，看该出来的是不是出来了。
