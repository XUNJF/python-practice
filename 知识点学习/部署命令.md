# 部署命令汇总（2026-11-07 实战记录）

**目标**：把 `day46-47` 的笔记助手从「本机能跑」变成「公网能访问」。

**成果**：`http://1.14.71.104:8000/?key=口令` —— 阿里云轻量（成都，2核2G4M，Ubuntu 22.04），Docker 部署。

---

## 整体流程

```
本地写代码
  ↓  git push
GitHub
  ↓  git pull
服务器
  ↓  docker build（按 Dockerfile 装环境）
镜像
  ↓  docker run（起容器、注入环境变量、映射端口）
公网可访问
```

**★ 关键理解**：容器跑的不是服务器上的代码文件，而是**镜像里那份冻结的副本**。所以改了代码必须重新 build + 重新 run。

### ② `day46-47/Dockerfile`

```dockerfile
FROM python:3.12-slim                    # 基础镜像：精简版 Python 3.12（自带 pip）
WORKDIR /app                             # 容器里的工作目录
ENV PYTHONUNBUFFERED=1                   # 日志不缓冲，docker logs 能立刻看到
COPY requirements.txt .                  # 先只拷依赖清单
RUN pip install --no-cache-dir -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
                                         # ↑ 单独成层，改代码时这层走缓存，不用重装依赖
COPY *.py ./
COPY index.html ./
COPY chroma_db ./chroma_db               # 向量库必须进去，否则检索没数据
RUN mkdir -p data                        # LangGraph 的 SqliteSaver 往这里写记忆
EXPOSE 8000                              # 声明用 8000 端口（说明性质）
CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]
                                         # 0.0.0.0 必须，127.0.0.1 容器外连不进来
```

### ④ `server.py` 加访问口令中间件

```python
ACCESS_KEY = os.environ.get("APP_ACCESS_KEY", "")   # 没设就是空字符串

@app.middleware("http")                              # 拦在【所有】请求前面
async def check_access(request, call_next):
    if not ACCESS_KEY: return await call_next(request)   # 没设口令 → 全放行（本地开发）
    supplied = request.query_params.get("key") or request.cookies.get("access_key")
    if supplied != ACCESS_KEY:
        return JSONResponse({"detail": "需要访问口令"}, status_code=401)
    response = await call_next(request)
    if request.query_params.get("key") == ACCESS_KEY:
        response.set_cookie("access_key", ACCESS_KEY, httponly=True, max_age=7*86400)
        # 从网址带上来的 → 种 cookie，7 天不用再带；httponly = JS 读不到
    return response
```

## C. 服务器环境（OrcaTerm 网页终端）

**登录**：控制台 → 实例 → 服务器登录 → 「免密连接 (TAT)」→ 登录

### 体检

```bash
whoami                        # 确认是 ubuntu（不是 root；要管理员权限用 sudo）
cat /etc/os-release | head -2 # 确认 Ubuntu 22.04
free -h                       # 内存、swap
df -h /                       # 磁盘
nproc                         # CPU 核数
```

### ① 加 2G swap

```bash
sudo fallocate -l 2G /swapfile               # 建 2G 文件当交换空间
sudo chmod 600 /swapfile                      # 只有 root 可读写（不改会报错）
sudo mkswap /swapfile                         # 格式化成 swap
sudo swapon /swapfile                         # 启用
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # 写进 fstab，否则重启就没了
free -h                                       # 验证：多出 Swap 那一行
```

### ② 装 Docker

```bash
sudo apt update
sudo apt install -y docker.io            # -y = 一路 yes
sudo systemctl enable --now docker       # 开机自启 + 立刻启动
sudo docker --version
```

### ③ 测镜像源（关键）

```bash
curl -s -o /dev/null -w "%{http_code}\n" --max-time 10 https://registry-1.docker.io/v2/
# → 000 = Docker Hub 被墙
curl -s -o /dev/null -w "%{http_code}\n" --max-time 10 https://docker.m.daocloud.io/v2/
# → 401 = 通（401 是「要认证」，不是「连不上」）
sudo docker pull docker.m.daocloud.io/library/hello-world
```

**实测结果**：Docker Hub `000`（被封），`docker.m.daocloud.io` 可用。
**其他可用的**：`ghcr.io`、`registry.cn-chengdu.aliyuncs.com`、`docker.1panel.live`（都是 401 = 通）。

## E. 运行

### ① 建 `.env`

```bash
nano .env        # 或 vim
```

```
DEEPSEEK_API_KEY=sk-...
SILICONFLOW_API_KEY=sk-...
APP_ACCESS_KEY=12位以上字母数字口令
```

```bash
chmod 600 .env                # 只有自己可读写
sed 's/=.*/=<隐藏>/' .env     # 确认变量名对、不泄露值
```

### ② 启动

```bash
sudo docker run -d --name notes --restart unless-stopped -p 8000:8000 --env-file .env notes-agent:v1
#                ↑         ↑                      ↑                  ↑                ↑              ↑
#             后台运行   起个名字        开机自启+崩了自动重启   服务器:容器端口   注入环境变量    用哪个镜像
```

**★ `--restart unless-stopped` 服务器必备**（不加机器一重启服务就没了）；本地测试用 `--rm` 正好相反。

**★ `-p 8000:8000` 左边是阿里云服务器的端口，右边是容器内部的端口。** 写成 `-p 9000:8000` 就是外面用 9000。

### ③ 看日志

```bash
sudo docker logs -f notes              # 持续跟踪；Ctrl+C 退出（不停容器）
sudo docker logs --tail 20 notes       # 只看最后 20 行
```

成功标志：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000
```

### ④ 改口令后重启

```bash
sudo docker stop notes && sudo docker rm notes
sudo docker run -d --name notes --restart unless-stopped -p 8000:8000 --env-file .env notes-agent:v1
```

**★ 只改 `.env` 不重启没用 —— 容器读的是启动那一刻的值。**

## F. 排查

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000
# 200 → 服务没问题，问题在防火墙
# 000 → 服务挂了，去看 docker logs

sudo docker ps                  # 运行中的容器
sudo docker ps -a               # 含已停止的
sudo docker exec -it notes ls /app    # 进容器看文件
sudo docker images              # 镜像列表 + 大小
```

**三层定位法：**

```
浏览器打不开
  ↓ ① 外面：防火墙 8000 开了吗？
  ↓ ② 服务器：curl 127.0.0.1:8000 返回 200 吗？
  ↓ ③ 容器：docker ps 里有 notes 吗、logs 报什么错？
```

## 踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| Docker Hub 被墙 | `docker pull` 报 `i/o timeout` | 换 `docker.m.daocloud.io` 镜像源 |
| 用户名错 | `ssh root@...` → `Permission denied` | Ubuntu 镜像默认用户是 `ubuntu` |
| 忘了 commit | `git push` 后服务器 `git pull` 还是旧的 | 必须 add → commit → push |
| 目录跳回 home | `unable to evaluate symlinks in Dockerfile path` | OrcaTerm 重连回 `~`，每次先 `cd` |
| 容器名冲突 | `Conflict. The container name "/notes" is already in use` | `sudo docker rm -f notes` |
| `.env` 权限太宽 | `-rw-r--r--` | `chmod 600 .env` |
| 改了 `.env` 不重启 | 口令没变 | `stop` + `rm` + 重新 `run` |
| 端口没开 | 服务在跑但浏览器打不开 | 控制台防火墙加 TCP 8000 |
